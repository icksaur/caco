# spec-session-orchestration

Document of record for **session orchestration (herds)**: a *parent* session that starts, messages, and supervises other ordinary Caco sessions (its *children*), never blocks on them, and is re-woken with the herd's state whenever a child needs attention. The structure is durable — it survives server restart, laptop sleep, and crash while Caco runs.

## Goals

A user talks to one parent session. The parent starts and/or acquires other top-level sessions as its children and gives them work **without blocking** — it finishes its turn and goes idle. **Children are ordinary sessions: they are not told they are children, need no special prompt or behavior, and simply receive a prompt, act, and respond as usual.** All herd awareness lives on the parent side. Whenever a child stops working (goes idle) the parent is re-woken with the full herd state so it can read each child's result and decide what's next — give a child more work, or disown it. The parent may only rest once every child is either still working or disowned. All children stay visible as **top-level** sessions. After any restart/sleep/crash the parent is re-woken to reassess its herd from durable state.

## Design

**Definitions.**
- **Parent** — a session that has ≥1 child. The role is **derived, not stored**: a session is a parent iff some other session claims it (see `orchestratedBy`). No parent-side flag or child list is persisted.
- **Child** — any ordinary session that a parent claims via the durable `orchestratedBy` field (= its parent's session id). Being a child is a **bond on the child's own metadata**; the child's kind, prompt, and behavior are unchanged and it does not know it is in a herd.
- **Herd** — the group formed by a parent and its children. Herds are **flat (depth 1)**: a child cannot itself be a parent (Guardrail 1 below), so a herd is exactly one parent plus a set of children — never a deeper tree. Herd operations are parent-relative — "the herd" from a tool's view means the caller's own children.

**Children are unaware by construction.** Nothing injects herd instructions, a system prompt, or special tools into a child. A child receives its prompt through the normal agent-message path (`source: 'agent'`, a `[agent:…]` prefix — the same a `task`/`create_caco_session` child already gets) and responds normally. Every herd mechanism — the wake, the state tool, the drain loop — runs on the **parent** and in Caco's server, never in the child. This keeps children reusable as plain sessions and means acquiring an existing session into a herd changes nothing about how that session behaves.

**Durable state.**
- Child: `orchestratedBy?: string` — its parent's session id (the herd bond; distinct from the overloaded `parentSessionId` used by fork/agent lineage). This single field, stored in the child's own `meta.json`, is the entire durable representation of *membership*.
- Parent: `herdStallCount?: number` and `herdWakeSignature?: string` — the stall-guard counter and the signature of the herd state at the last wake (Guardrail 2 below). These are the **only** parent-side fields, and they are single-writer (only the server's wake path and the parent's own `caco_herd resume` write them), so they do **not** reintroduce the reverse-index read-modify-write race the derived-role design avoids. The parent's *role* and *child set* remain fully derived by scanning `orchestratedBy === self` — nothing about membership is stored on the parent.

A child's status, its last result, and when it went idle are still derived from state Caco already persists: live busy/idle state, `meta.lastIdleAt`, and the child's event history. There is **no `readyAt`/`drainedAt` flag and no *durable* parent-side child index**. "This child needs the parent's attention" is *derived*: a child needs attention iff it is in the herd **and not currently active (busy)**.

**Membership index (in-memory, rederivable — S2).** Resolving "am I a parent, and which children?" by scanning every session's `meta.json` on every `session.idle` is an O(N) synchronous-disk cost paid even by non-herd idles. To avoid it, Caco keeps an **in-memory** `Map<parentId, Set<childId>>` (or a `Set<parentId>` + per-parent child scan), **rebuilt from disk on boot** and updated by the four bond writers (`caco_herd create`/`acquire`/`disown`, and self-heal). Because it is in-memory and fully rederivable from the children's `orchestratedBy` fields, it is **not** a durable reverse-index and reintroduces **no** cross-session write race — the child's `meta.json` remains the single source of truth; the index is a derived cache. A cache miss/staleness at worst falls back to a disk scan; it never decides membership authoritatively.

**The non-blocking contract.** After giving children work the parent does **not** wait — it completes its turn and goes idle. This is the difference from `caco_session_delegate` (which blocks the caller until the target replies) and is why a herd scales to many children and survives restarts: the parent holds no in-memory wait; all progress is driven by idle transitions and the boot scan.

**Reading child results — `caco_herd_state`.** The parent's go-to tool. It returns, for **every** child of the caller: `sessionId`, `name`, `status` (busy/idle/inactive), `lastIdleAt`, and the child's **last assistant message** (byte-bounded via `boundDelegateResponse`). This closes a real API gap: today `get_session_state` / `GET /sessions/:id/state` returns status/cwd/model/kind/intent but **not** the last response, and the only code that reads a session's last response is `getLastAssistantMessage`, private to `delegate-tool.ts`. That helper is extracted into a shared module so `caco_herd_state` returns each child's result in one call — the parent never needs to know history APIs, exactly as the `task` tool returns a subagent's result automatically.

**Herd control — `caco_herd`.** One tool, an `action` enum. `create` and `acquire` **fail if the caller is itself a child** (Guardrail 1):
- `create` — start a **new** session (cwd, model, prompt), stamp `orchestratedBy = self`, dispatch the prompt non-blocking. This is how a fresh child is born.
- `acquire` — adopt an **existing** unowned session (`sessionId`) into the herd (set `orchestratedBy = self`), optionally dispatching a prompt. Rejected if the target is already a child of a different parent, is the caller itself, or would form a cycle.
- `resume` — give an **existing** child (already in the herd) more work: dispatch a prompt, making it active again. On success it **resets the parent's `herdStallCount`** (real progress — Guardrail 2). ("Resume the child's work" — the herd verb, not the internal session-resume.)
- `disown` — remove a child from the herd (clear `orchestratedBy`). The child reverts to a normal top-level session, `caco_session_delegate` works on it again, and it no longer keeps the parent awake. This is how the parent marks a child "done."

All dispatches (`create`/`acquire`/`resume`) go through the existing agent-message path (`source: 'agent'`, `fromSession`, `correlationId`), so the **runaway guard** (`checkAgentCall`/`recordAgentCall`, depth/rate/age limits in `session-manager.ts`) applies unchanged. Runaway *hierarchies* are additionally foreclosed by Guardrail 1 (flat, depth-1 herds), and runaway *re-prompting* by Guardrail 2 (the stall guard).

**Child-prompt rendering (agent color).** A prompt a parent sends a child must be visually distinguishable from a prompt the human typed. The color derives from a persisted content prefix, not a transient field: the message route applies `[agent:<fromSession>]` **only when BOTH `source==='agent'` AND `fromSession` are present** (`src/routes/session-messages.ts:185`); the SDK echoes that prefixed content back, `enrichUserMessageWithSource` re-parses the prefix (`src/routes/websocket.ts:326`), and the client maps the source-tagged `user.message` to `caco.agent` → `.agent-message` → `--color-agent-bg` (`public/ts/dom-regions.ts:668`, `public/style.css:892`). So a `caco_herd` dispatch must send **both `source:'agent'` and `fromSession = parentId`** (the herd already routes through the agent path with the parent as `fromSession`), and it renders agent-colored on live view AND on history replay. **Alignment (M3):** `caco_session_delegate` today posts `{prompt}` with neither field (`src/delegate-tool.ts:140`), so its prompts persist unprefixed and render *user*-colored. To honor "distinguish user from agent prompts," the delegate send must pass **`source:'agent'` AND `fromSession = sessionRef.id`** (setting `source` alone would still persist no prefix → still user-colored). After this every agent→session prompt (herd or delegate) carries `[agent:<callerId>]` and shares `--color-agent-bg`; a human's prompt keeps the user color. **Side-effect to accept (S1):** `needsObservation` is `!source` (`session-messages.ts:199`), so giving delegate a source stops marking the delegated session user-unobserved on idle and stops the `!source` `lastUsedAt` stamp (`:191`). This is intended — a delegate reply is parent-observed, not user-observed — but it is a real behavior change, not a no-op.

**Wake machinery — one funnel, three sources.** All call `wakeParentIfNeeded(parentId)`, which re-prompts an **idle** parent with a system message **plus** the current `caco_herd_state` summary iff **not all of its children are active** (≥1 child is idle/inactive):
1. **A child goes idle** — hooked at the `session.idle`/`session.error` branch of `handleEvent` (`src/routes/session-messages.ts:451-458`), NOT the generic `completeDispatch` teardown (which also runs for `'timeout'`/`'send error'`/`'no-session'` and must not stamp idle or fire wakes). It runs **outside** the `needsObservation` gate so agent/system-sourced child turns still trigger. Resolve the child's `orchestratedBy` via a typed `ok|missing|corrupt` read:
   - Parent **missing** (deleted) → **self-heal**: clear this child's `orchestratedBy` (it reverts to a normal session); no wake.
   - Parent **corrupt** (possibly a transient mid-write read) → **skip + log**, do NOT clear the bond (matching the corrupt-child posture, §Considerations) — a transient corruption must not permanently orphan a live herd.
   - Parent **present** → `wakeParentIfNeeded(parent)`.
2. **The parent goes idle** → `wakeParentIfNeeded(self)`. This is the enforcement: a parent that goes idle while any child is not active is immediately re-woken with the herd state. It converges only when the parent has made every child active (via `resume`) or disowned it.
3. **Server boot** — a **post-listen** phase. `startScheduleManager()` and friends run *before* `server.listen()` (`server.ts:311` vs `:340`), so the herd boot scan must run **inside the `server.listen(...)` callback** (or dispatch **in-process** via `dispatchMessage`, not an HTTP POST) — a pre-listen scan whose wake POSTs to `/api/sessions/:id/messages` would fail because the server is not yet accepting connections. Scan for parents with ≥1 non-active child and wake each; self-heal any child whose parent is gone. This is the restart/sleep/crash recovery.

`wakeParentIfNeeded(parentId)` — **serialized per parent, trailing-edge** by a per-parent promise chain (exactly `session-state`'s `runTransition` pattern, `src/session-state.ts:82` — the next call chains after the current one and then **re-evaluates live status**, NOT leading-edge single-flight which would drop the trailing call). Trailing-edge is required for liveness: if it were single-flight (`quota-poller.ts:37`-style "return the in-flight promise"), a child that idles *during* an in-flight evaluation that already decided "all active, no wake" would be coalesced onto that stale decision, nothing would be dispatched, the parent would never re-enter busy→idle, and the idle child would never be drained. With trailing-edge, the second trigger runs *after* the first completes and re-reads live status, so the newly-idle child is seen. The chain also closes the async-busy window (marking the parent busy via POST→`dispatchMessage`→`startDispatch` is not instantaneous, so two concurrent triggers could otherwise both read not-busy and both dispatch). The in-memory chain is not durability-critical — it only orders evaluations; durability comes from the meta flags + live status re-read.
- Gather the parent's children; if all are active (busy), return — the parent legitimately rests while its herd works.
- Parent **busy** → return (don't inject; the parent-idle trigger re-fires when it frees — nothing lost, membership is durable and status is live).
- **Stall guard (Guardrail 2)**: compute the current herd **signature** (see below). If **every** child is inactive (none busy) **and** the signature equals `herdWakeSignature`, this is a no-progress repeat: increment `herdStallCount`; if it exceeds `HERD_STALL_LIMIT` (10), **suppress the wake** (return without injecting) — the parent is stuck and is left idle rather than re-prompted forever. Otherwise (any child busy, or the signature changed) reset `herdStallCount = 0`. Always store the new signature. **The counter increments only on an actually-dispatched wake** — a suppressed or busy-deferred attempt does not increment (so the threshold counts real re-prompts, not evaluations).
- Else inject one `[system]` wake carrying a compact herd-state summary: `[system] Your herd has N child session(s) awaiting attention. Their state: … Call caco_herd_state for full results, then resume or disown each.` The wake is `source:'system'` with **no `fromSession`**, so the route requires **no correlationId** (the `fromSession && !correlationId` guard does not fire, and the runaway guard is keyed on a present `correlationId`). **Slice C (M2):** to bound an active resume-churn runaway, the stall-guard slice introduces a **stable per-herd correlationId** reused across wake→resume so `checkAgentCall` accumulates — but note it must not naively reuse the depth-based agent correlation (a stable id records each distinct child target, and `collapseChain` would count >`maxDepth` distinct children as excessive depth); C2 either uses a dedicated herd rule or the parent-return collapse (wake→parent, resume→child keeps depth ~2). In Slice B, `caco_herd` dispatches simply use the **caller's live dispatch correlationId** (as `create_caco_session`/`caco_session_delegate` do), which is depth-safe and already runaway-guarded.

**Guardrails.**

*Guardrail 1 — children cannot have children (flat herds, no runaway HERD hierarchy).* `caco_herd`'s `create` and `acquire` actions **fail hard** when the **caller** is itself a child (its own `orchestratedBy` is set): a child may not start or adopt *herd* children. This caps every **herd** at depth 1. It intentionally does **not** restrict a child from using the ordinary `create_caco_session`/`task` tools — those spawn plain (non-herd) sessions with no `orchestratedBy`, bounded by the existing correlation runaway guard, and are not herd members. Guardrail 1 bounds herd depth specifically; general session spawning stays governed by the runaway guard. (`resume`/`disown`/`caco_herd_state` are also child-inapplicable: a child has no herd of its own.)

*Guardrail 2 — no-progress stall guard.* A parent that is repeatedly re-woken with **the same fully-inactive herd state** — every child idle/inactive and nothing changing — is making no progress; after `HERD_STALL_LIMIT` (10) consecutive such **dispatched** wakes the automatic re-wake is **suppressed** (see `wakeParentIfNeeded` above), so a wedged herd stops burning turns. The **herd signature** is a cheap hash over each child of `sessionId:status:lastIdleAt`. This relies on the **unconditional `lastIdleAt` stamp** (Plan Step 5) — `markIdle` alone is `needsObservation`-gated and skips agent-sourced child turns, so without the unconditional stamp the signature could look unchanged after a real re-run and suppress prematurely. With it: a child that re-ran and re-idled advances its `lastIdleAt` (signature changes); a disowned/added child changes the id set; a child that went busy changes its status. Any such change resets `herdStallCount` to 0. In particular, a **successful `caco_herd resume`** (post-dispatch-success only — a failed resume does not reset) makes a child active and resets the counter explicitly. Suppression halts only the *automatic* wake; a user turn (or any turn that resumes/disowns a child) changes the signature and re-enables waking, so a human can always rescue a stalled herd. The counter and signature live on the parent's `meta.json` (single-writer, via the serialized `wakeParentIfNeeded` + the parent's own tool calls). The **boot scan explicitly resets `herdStallCount`/`herdWakeSignature`** for each parent it evaluates, so a restart deterministically grants the herd a fresh `HERD_STALL_LIMIT` (rather than relying on the emergent `idle`→`inactive` status flip) — a clean "restart is a new chance" policy.

**Reliable child idle-stamping.** `caco_herd_state` reports each child's `lastIdleAt` and the stall signature keys on it — but in the **live** path `lastIdleAt` is currently written only by `unobservedTracker.markIdle`, which is **gated by `needsObservation`** and therefore **skipped for `source:'agent'` child turns** (`src/routes/session-messages.ts:452`, `unobserved-tracker.ts:55`). An unconditional stamper **already exists**: `markSessionIdle(sessionId)` writes `lastIdleAt` and is exported + tested (`src/session-meta-store.ts:187`, `src/storage.ts`, `tests/unit/storage.test.ts`) — it is simply not wired into the live idle path. So the child-idle herd hook (Step 5) **reuses `markSessionIdle`**, calling it unconditionally on every `session.idle` (independent of `needsObservation`), so an agent-sourced child still reports a fresh idle time. This is separate from `markIdle`'s user-observation bookkeeping (which stays gated) — it is the herd's durable "last stopped working" signal.

**Herd info on parent wake.** The current herd-state summary is delivered by exactly one path: the `[system]` **wake message** that `wakeParentIfNeeded` injects. That single, well-defined dispatch is how the parent re-enters with herd context ("herd info is sent when resuming a parent" — Caco *resumes* the parent by dispatching the wake, which carries the summary). There is deliberately **no** separate "inject on any activation" hook — that would risk duplicate/late injections. A parent the *user* opens is not force-injected; it calls `caco_herd_state` on demand, and if any child is pending it is woken on its next idle regardless. The full detail is always one `caco_herd_state` call away.

**System message source (full render wiring — S6).** Adds `'system'` to the `MessageSource` union (`src/message-source.ts:13`, today `user|applet|agent|scheduler|skill`). The wake path composes its payload with `prefixMessageSource('system', 'herd', body)` and posts with `source:'system'`; the message route gains a `system` branch alongside the existing `applet`/`agent`/`scheduler` prefixing (`src/routes/session-messages.ts:183-189`). The client already maps a source-tagged `user.message` to `caco.<source>` (`public/ts/dom-regions.ts:667`), so rendering `caco.system` requires wiring **all four** places the other sources appear or the box renders blank/unstyled: `EVENT_TO_OUTER` (`dom-regions.ts:92`), `EVENT_TO_INNER` (`:152`), the content-setter map (`:580`), and a `.system-message` CSS rule (`public/style.css`, near `.scheduler-message:926`); plus a `system` branch in `enrichUserMessageWithSource` (`websocket.ts:346-349`). Rendered distinctly (its own subtle background) and, like scheduler/agent sources, it does **not** mark the parent "unobserved" for the user (`needsObservation` stays false for non-user sources).

**User-observation and herd-attention are orthogonal.** "Unobserved by the user" (`unobservedTracker`/`lastObservedAt` → the UI dot, cleared when the *user* opens the session) and "needs the parent's attention" (a child being idle-in-herd → cleared when the parent resumes or disowns it) are independent systems. A child completes via a non-user source (`needsObservation=false`), so its completion never sets the user dot; and herd handling never touches the user dot. A session can be user-unobserved, herd-pending, both, or neither, independently.

## Invariants

- **Children are unaware** (invariant): no herd prompt, tool, or behavior is injected into a child; herd logic lives only on the parent and in the server. Acquiring/disowning a session must not change how that session itself behaves. (A child *sees* its prompt as an agent-sourced message — the same it already gets from `create_caco_session`/`task` — which is display metadata, not behavior.)
- **Agent-colored cross-session prompts** (invariant): a prompt sent from one session to another (herd `caco_herd` or `caco_session_delegate`) carries `source: 'agent'` so it renders with `--color-agent-bg`, visually distinct from a human's own message. A human's typed prompt is never agent-colored.
- **Role derived, never stored** (invariant): a parent has no persisted *membership* (no child list, no `isParent` flag); the role and child set are computed by scanning `orchestratedBy === self`. The only parent-side fields are the stall-guard counter/signature, which are single-writer and orthogonal to membership, so the bond still has exactly one writer (the child) and cannot desync.
- **Flat herds — children cannot have children** (invariant, Guardrail 1): `caco_herd create`/`acquire` fail when the caller has `orchestratedBy` set. Every herd is depth 1; runaway hierarchies are structurally impossible.
- **Bounded no-progress** (invariant, Guardrail 2): after `HERD_STALL_LIMIT` consecutive wakes with an unchanged fully-inactive herd signature, automatic re-wake is suppressed; any signature change (notably a successful `caco_herd resume`) resets it. A parent can never be auto-re-prompted forever on a stuck herd.
- **Durable-by-disk** (invariant): the only persisted herd state is each child's `orchestratedBy`; everything else is derived from state Caco already persists (live status, `lastIdleAt`, history). A restart/sleep/crash must leave the parent re-woken to reassess every non-active child.
- **Non-blocking parent** (invariant): the parent never synchronously waits on a child; progress is driven only by idle transitions + the boot scan.
- **Rest only when settled** (invariant): a parent that goes idle while any child is idle/inactive is re-woken; it converges only by making every child active or disowned. The stall guard (Guardrail 2) bounds a non-converging parent to `HERD_STALL_LIMIT` no-progress wakes; the correlation runaway guard bounds per-turn churn.
- **Children are not delegatable** (invariant): while `orchestratedBy` is set, `caco_session_delegate` targeting that child fails — its lifecycle is owned by the herd, and a blocking third-party delegate would fight it.
- **No wake to a busy parent** (invariant): a wake is injected only into an idle parent; a busy one is retried on its next idle, never queued in memory; at most one wake in flight per parent.
- **Orphans self-heal** (invariant): a child whose `orchestratedBy` resolves to a missing/corrupt session clears its own bond on its next idle and on the boot scan — no child is stuck pointing at a dead parent.
- **Runaway guard preserved** (invariant): parent↔child messaging goes through `checkAgentCall`; the herd adds no bypass.

## Considerations

- **The result API gap is the crux for usability**: `caco_herd_state` bundling each child's last assistant message (via the extracted `getLastAssistantMessage` + `boundDelegateResponse`) is what makes "the parent gets each child's result easily" true — without it the parent has only `get_session_state` (status, no content) and no ergonomic way to read a child's answer.
- **"Needs attention" is derived from live status, not a flag**: this means it is always correct after a restart (no child is active post-restart → the parent is woken to reassess) with no stored flag to reconcile. The tradeoff: an idle child the parent has *not yet* disowned keeps re-prompting — that is the intended "drain-all-or-be-re-prompted" behavior, and the parent converges by disowning.
- **Convergence & loops**: the wake message instructs the parent to resume-or-disown each pending child; a well-behaved parent empties the pending set in one turn. A parent that ignores it is bounded twice: Guardrail 2 suppresses the automatic wake after `HERD_STALL_LIMIT` no-progress repeats, and the runaway guard caps per-turn churn. Suppression is not a dead end — a user turn (or any resume/disown) changes the signature and re-enables waking.
- **Stall signature vs "content changed"**: the signature keys on `lastIdleAt` (advanced by our unconditional idle stamp) rather than message content, so a child that genuinely re-ran counts as progress even if it produced the same text, while a child that never re-ran does not — cheap and good enough for the *no-progress* (nothing running, nothing changing) case Guardrail 2 targets. It does **not** bound a child that keeps re-running with an identical error: each re-run advances `lastIdleAt` (signature changes → `herdStallCount` resets), so the stall guard never fires. That runaway is instead bounded by the **stable per-herd correlationId** threaded through wake→resume (above): the correlation runaway guard accumulates the repeated resumes and trips. Both bounds are needed — the stall guard for *inactive* stalls, the correlation guard for *active* churn.
- **Busy parent during a child completion**: no message is enqueued; the child's idleness is durable-enough (it stays idle), so the parent's own next idle re-derives it and wakes. The durable membership + live status *is* the queue.
- **Crash mid-handling**: nothing to un-wind — there is no readyAt flag to clear. On boot, non-active children re-trigger the wake; `caco_herd_state` re-reads durable results (reading a last message twice is harmless).
- **Acquire semantics**: acquiring sets only the bond; the acquired session keeps its identity, history, and behavior. A session already in another herd is rejected (one parent per child). Self/cycle targets are rejected.
- **Concurrent-activity cap (O1)**: `MAX_ACTIVE_SESSIONS = 5` (`session-manager.ts`) caps how many sessions are *live in memory* at once. Durable herd membership scales to many children, but only ~5 can be actively running concurrently; a larger herd thrashes the resume/evict path. "Scales to many children" is a *membership/durability* claim, not a concurrent-execution one.
- **No restart-loop from the stall reset (O3)**: resetting `herdStallCount` on boot cannot drive a runaway, because restarts are not wake-driven — nothing makes the server restart in response to a wake, so "restart → fresh chance" cannot self-trigger.
- **Frontend**: children stay top-level (unlike hidden swarm sessions, `session-panel.ts` `kind !== 'swarm'`); an orchestration badge/affordance is desirable but the requirement is only that all sessions remain visible and independently openable. A derived herd badge (a session some child claims; a session with `orchestratedBy`) is computed from the in-memory index, not a stored flag.

## Risks and Mitigations

- **Re-prompt loop burns tokens**: a parent that neither resumes nor disowns a pending child re-wakes each idle; hard-bounded two ways — the stall guard (Guardrail 2) suppresses automatic re-wake after `HERD_STALL_LIMIT` no-progress (inactive) repeats, and the correlation runaway guard — fed by the **stable per-herd correlationId** threaded through wake→resume — caps *active* churn (a child repeatedly resumed with identical results, which advances `lastIdleAt` and so slips past the stall signature).
- **Runaway hierarchy**: foreclosed by Guardrail 1 — a child cannot create/acquire children, so herds are depth 1 with no recursion to bound.
- **Wake storm** (many children idle at once): each child idle calls the funnel, but the first wake marks the parent busy so the rest coalesce into the next parent-idle; `caco_herd_state` reads *all* children, so one wake surfaces every result — bounded to one in-flight wake per parent.
- **Lost wake across restart**: recovered by the post-listen boot scan; the source of truth is disk (the bond) + live status.
- **Orphaned children** (parent deleted/crashed): two layers — proactively clear children's `orchestratedBy` on parent delete, and each child self-heals on its next idle / the boot scan if its parent is gone.
- **Result too large**: each child's last message is byte-bounded (`boundDelegateResponse`) so a multi-child `caco_herd_state` stays under the output-shaper threshold, as `caco_session_delegate` already does.
- **Corrupt child meta**: typed `ok|missing|corrupt` reads skip a corrupt child in the scan (never crash the wake), matching the scheduler/unobserved posture.

## Acceptance

- Observable: a parent uses `caco_herd` to start/acquire ≥2 children and give them work, then goes idle; while all children are busy the parent rests; as each child finishes, the parent is re-woken with a `[system]` message + herd summary and `caco_herd_state` returns every child's status and last response; the parent `disown`s finished children and `resume`s others; once every child is active-or-disowned the parent rests; restarting the server mid-herd re-wakes the parent to reassess. Children behave as ordinary sessions throughout (no herd-specific prompt or tools).
- Budgets: at most one in-flight wake per parent; `caco_herd_state` results byte-bounded under the output-shaper threshold.
- Gates: typecheck ×2, lint:strict, knip, full tests (`npm test`, coverage thresholds), build:client.
- Oracles:
  - `wakeParentIfNeeded` — hand cases: all children active → no wake; ≥1 non-active + parent idle → one wake with correct N + summary; parent busy → no wake; child idle + parent idle → wake; child idle + parent busy → no wake (deferred).
  - child-idle branching — parent present → wake; parent **missing** → self-heal (bond cleared), no wake; parent **corrupt** → skip + log, bond **preserved** (no orphan on transient corruption).
  - `caco_herd_state` — returns all children with status + `lastIdleAt` + last response; last response byte-bounded; empty herd → empty list.
  - `caco_herd` actions — `create` stamps bond + dispatches; `acquire` sets bond (+ optional dispatch), rejects already-owned/self/cycle; `resume` dispatches to a member; `disown` clears bond (→ delegatable again).
  - **Guardrail 1** — `create`/`acquire` called by a session that itself has `orchestratedBy` set → hard error (children cannot have children).
  - **Guardrail 2 (stall guard)** — N (=`HERD_STALL_LIMIT`) consecutive **dispatched** wakes with an unchanged all-inactive signature → the (N+1)th is suppressed; a signature change (child re-idled with new `lastIdleAt`, disown, add, or a successful post-dispatch `resume`) resets the counter and re-enables waking; a suppressed/busy attempt does not increment; the counter/signature persist on the parent's meta (single-writer); the boot scan resets them.
  - **Active-churn bound (M2)** — a parent that repeatedly `resume`s an identically-erroring child (each run advancing `lastIdleAt`, so the stall guard never fires) is bounded by the **stable per-herd correlationId** threaded wake→resume: `checkAgentCall` accumulates and trips the runaway guard. (Without the shared correlationId this loop is unbounded.)
  - **Trailing-edge coalescing (M1)** — `wakeParentIfNeeded` is per-parent **queued** (re-evaluates after the in-flight call); a child that idles *during* an in-flight "all-active → no wake" evaluation is still woken by the trailing re-evaluation. Two concurrent calls over an **unchanged** herd yield one dispatched wake; a herd that *changed* between them yields a second. (A leading-edge single-flight that drops the trailing call is a liveness bug — explicitly rejected.)
  - delegate guard — `caco_session_delegate` targeting a child (`orchestratedBy` set) → child-error; disowned child → delegatable.
  - unaware-child — a child receives a normal agent-sourced (`[agent:…]`) prompt with no herd system message/tools; acquiring a session injects nothing into it.
  - child-prompt color — a `caco_herd` dispatch sends **both `source:'agent'` and `fromSession=parentId`**, so the persisted content carries the `[agent:<parentId>]` prefix and renders `caco.agent` → `.agent-message` (`--color-agent-bg`) on live AND replay; after alignment a `caco_session_delegate` prompt (source:'agent' + fromSession=callerId) renders the same; a human's prompt (no prefix) stays user-colored. (Setting `source` without `fromSession` persists NO prefix → still user-colored — a fake-pass to avoid.)
  - boot scan — parent with a non-active child on disk → woken **inside the listen callback** (post-listen; a pre-listen wake would 404); child with a **missing** parent → bond cleared; busy parent → deferred, not double-woken.
  - idle-stamping — a child that ran as `source:'agent'` still gets `lastIdleAt` written on idle via `markSessionIdle` (unconditional), so `caco_herd_state`/the signature see a fresh idle time.

## Rationale

Most primitives already exist: non-blocking parent-linked child creation (`create_caco_session`: `parentSessionId` + fire-and-forget), idle detection (`session.idle`/`unobservedTracker`), message injection into an idle session (the scheduler's `source`-tagged POST), durable per-session metadata with typed corrupt-safe reads, a boot hydrate hook, and a correlation runaway guard. Two things are genuinely missing and this spec supplies them: (1) a **non-blocking, ergonomic result read** — no current tool returns a session's last response (`get_session_state` omits it, `getLastAssistantMessage` is private) — delivered by `caco_herd_state`; and (2) a **durable supervise/re-wake loop** that keeps a parent engaged with idle children, delivered by the `orchestratedBy` bond + `wakeParentIfNeeded`.

Two design choices carry the weight. First, **children are unaware**: all herd logic is parent-side + server-side, so any ordinary session can be a child with zero behavioral change — the herd is a supervision layer, not a protocol the child must speak. Second, **role and readiness are derived, not stored**: a parent is "a session some child claims," and "needs attention" is "a herd child that isn't busy." The only *durable* herd state is the child's one-way `orchestratedBy` bond — a single writer, no durable reverse index, no readiness flag — which is what makes the structure race-free and trivially correct across restart/sleep/crash (re-derive from disk + live status on boot). A parent-side membership index and the wake-serialization queue exist only **in memory**, rebuilt from that disk truth on boot, so they accelerate without becoming a second source of truth. `caco_session_delegate` (blocking, 1–2 targets, returns a reply) remains for synchronous review/lookup; the herd is the asynchronous, many-child, durable, supervise-and-collect counterpart, and `caco_herd_state` is its automatic result channel — the equivalent of the `task` tool returning a subagent's answer, but for durable top-level sessions.
