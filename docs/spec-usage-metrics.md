# spec-usage-metrics

Durable, system-wide usage metrics: one record per completed request, persisted to disk and aggregatable for an applet, an HTTP API, and future automation. Extends the in-memory budget subsystem (`spec-budget.md`) with the persistence + query layer it lacks (spec-budget §Design: "all in-memory per session (nothing persisted across restart)").

## Goals

At the end of every request, durably record what it cost — tokens (fresh/cached/output), credits per class, model, and context window — keyed by session and timestamp. Aggregate that history performantly from disk (bounded I/O per query), expose it over HTTP, and surface it in a `usage` applet whose first view is hourly credit consumption for the past week. The data model supports arbitrary later pivots (per-model, per-session, per-hour spend) without a schema change.

## Design

**Collection point (single finalizer).** `completeDispatch` in `src/routes/session-messages.ts` is the request-completion owner for every route-observed exit: normal `session.idle`/`session.error` (session-messages.ts:414-421), watchdog timeout, no-session, and retry-failed all route through it. A **normal** cancel also flows here — `cancelSession` waits for the SDK's `session.idle`/`error`, which the dispatch subscription catches (session-manager.ts:1750-1755). Two bypasses exist and are handled deliberately (review finding): (a) **cross-provider model switch** tears down dispatch directly (session-manager.ts:1525) — closed by Plan 4's busy guard, so a switch can no longer happen mid-dispatch and there is nothing to finalize; (b) **forced-clear of an SDK-unresponsive session** (`cancelSession` → `endDispatch`, session-manager.ts:1732-1735,1757-1760) — **explicitly excluded** from durable usage: the session is wedged and its request counters are unreliable, and this already matches the existing bench-log behavior (which also only logs from `completeDispatch`). The usage record is built + emitted inside `completeDispatch`, alongside the existing bench-log append, under the same `requestTurns > 0` guard (so pre-send aborts emit nothing).

**Pricing context captured at dispatch START, not completion.** `getSessionMeta(sessionId).model` read only at completion is unsafe: model changes were allowed while busy (sessions.ts:674-682 had no busy guard, unlike the context-budget change at :686-688) and the fast path rewrites meta immediately (session-manager.ts:1507-1512), so a request's tokens could be priced under a model swapped in mid-flight. Fix (two parts): (1) **add a busy guard** to the model-change route — reject with 409 while a dispatch is in flight, matching the context-budget guard; (2) **capture `{ model, rates, contextWindow }` into the dispatch closure at dispatch start** (right after the `getSessionMeta` read at session-messages.ts:337, before `sendStream`) and price the record from that frozen context. The record's model/cost therefore describe the model that actually produced the tokens, independent of any concurrent change.

**Emit abstraction (one record, many consumers).** A `UsageRecord` is built once in `completeDispatch` and handed to consumers:
- `src/usage-metrics.ts` owns `buildUsageRecord(...)` (pure) + a global sink registry: `registerUsageSink(sink: UsageSink)` and `emitUsageRecord(record)` which fans out best-effort (a throwing sink never disturbs dispatch — same contract as `request-metrics-log`).
- Concrete sinks registered at server boot (`server.ts`): **`usageStoreSink`** (durable, this spec) and room for future sinks (rollups, external export) — the "any other consumers" extension point.
- The **footer** is the second consumer of the same record but is NOT a global sink: its broadcast target is the request-scoped `onEvent` callback, so it stays inline in `completeDispatch` (the existing throughput broadcast, now fed the same figures). Documented, not forced into the global registry.
- The existing **bench log** (`request-metrics-log.ts` → `requests.jsonl`, consumed by `scripts/bench-report.mjs`) is left untouched; the usage store is additive and richer. Not folded into a sink to avoid churning the bench row shape.

**`UsageRecord` shape** (the queryable columns; superset of the user's list):
`ts` (ISO), `sessionId`, `model` (slug | null when Auto/unknown — the model **captured at dispatch start**), `contextWindow` (number | null), `inputTokens` (fresh = requestIn), `cachedTokens` (requestCache), `outputTokens` (requestOut), `inputTokenCost`, `cachedTokenCost`, `outputTokenCost`, `requestCredits` (sum of the three, `null` when unpriced), `turns` (requestTurns). Costs are **credits, computed at finalize time** from the request tokens × the **captured** per-Mtok rates, then frozen into the record — rates drift, so cost is captured, never recomputed on read. When rates are unknown (Auto / unpriced), all four cost fields are `null` and only token counts persist (aggregation treats this distinctly — see below).

**Pure builder.** `buildUsageRecord({ sessionId, model, tokens, rates, contextWindow, ts, perTurn? })` → `UsageRecord`. No I/O, no lookups — tokens + rates in (optionally `perTurn` for per-turn attribution, see Amendment below), record out. Cost math mirrors the footer's class pricing (fresh×input + cached×cache + output×output, per-Mtok / 1e6). `rates: null` → all cost fields null. Server-side rate resolution reuses the footer's segment-boundary **variant fallback** (the `resolveModelRates` logic, so `-1m` / `-internal` variant ids still price); an oracle pins the arithmetic AND the variant/null/missing-rate behavior against footer golden numbers. (Historical note: an earlier draft of this line named a `snapshot` param; the shipped signature takes `tokens: UsageTokens`.)

**Durable store (bounded-partition aggregation).** `src/usage-store.ts`. Append-only JSONL **partitioned by UTC day**: `~/.caco/metrics/usage/YYYY-MM-DD.jsonl`. Rationale for partitioning over a single flat log: a time-window query (e.g. "past week") reads only the ≤ (window-days + 1) day-files intersecting the window instead of scanning all history — a **bounded partition count** (not literally bounded bytes; a single day-file is unbounded, but a day of local requests is small). Chosen over SQLite because the repo is deliberately zero-dep / file-based (schedule, memory, session-meta, bench log are all plain JSON/JSONL); a native DB dep is unjustified at this scale.
- `appendUsageRecord(record)` — `mkdir -p`, then **synchronous** `appendFileSync` of one `JSON.stringify(record) + '\n'` in append mode to the record's UTC-day file (exactly the atomic single-line-append the bench log uses — so concurrent appends from parallel sessions to the same day-file never interleave within a line). Best-effort; single-process assumption (no cross-process lock — documented, not built).
- `readUsageRecords(fromTs, toTs)` — read only the day-files whose date intersects `[from, to]`, parse (skip corrupt/partial lines like the bench log), filter to the exact window. Returns records ascending by `ts`. A small in-process cache keyed by `{path, mtime, size}` avoids re-parsing unchanged (completed, past-day) files on frequent applet polls.
- `aggregateHourly(fromTs, toTs)` — bucket `readUsageRecords` output into UTC-hour buckets; returns a **dense** array (every hour in the window present). Each bucket is `{ hour, credits: number | null, pricedRequests, unpricedRequests, inputTokens, cachedTokens, outputTokens }`: `credits` sums only priced requests; a bucket with requests but none priced has `credits: null` (distinct from a truly empty bucket's `credits: 0, pricedRequests: 0`). Null-safe summation — an unpriced record never coerces into a 0 that hides real usage. Pure over the read rows.

**HTTP API** (`src/routes/usage.ts`, mounted `/api` via `routes/index.ts`):
- `GET /api/usage/hourly?days=N` (default 7, clamped) → `{ from, to, buckets: [{ hour, credits, pricedRequests, unpricedRequests, inputTokens, cachedTokens, outputTokens }] }` (`credits` may be `null` for an all-unpriced bucket). The applet's first view.
- `GET /api/usage/records?from=&to=&limit=` → the **most recent** `limit` records in the window (newest first) + a `truncated` flag, for investigation/automation; `limit` clamped, window validated and its **width clamped to MAX_DAYS** (keeps the recent end) so an over-wide range can't drive an unbounded day-file scan. Exported testable helpers: `parseHourlyQuery` (days→[from,to] + clamp) and `parseRecordsQuery` (window/limit validation + width clamp → 400 message | params).

**Applet (`applets/usage/`).** Bundled 4-file applet (`meta.json`/`content.html`/`script.js`/`style.css`), opened at `/?applet=usage`, styled to `spec-style.md` tokens only (semantic `--color-*`/`--space-*`/`--radius-*`/`--font-*`; the `jobs`/`memories` applets are the clean references). First view: a bar chart of hourly credits for the past 7 days from `GET /api/usage/hourly`, rendered with pure CSS/inline-SVG bars (no chart dep — none exists in the repo). Header + refresh; loading/empty/error states. An **all-unpriced bucket** (`credits: null` but nonzero tokens) is rendered distinctly from an empty hour (e.g. a hatched/"unpriced" marker) so Auto usage never reads as zero spend. Other metrics (per-model, per-session pivots) are stubbed as "pending" — the API already returns the raw columns for them.

### Amendment: per-turn attribution (Auto-mode + multi-model)

**Motivation.** The dispatch-start `{model, rates}` capture (above) prices every turn of a request under one model. For an Auto-mode selection the captured model is `'auto'` (unpriced) → the record is tokens-only and the footer's credit headline hides. Reviewer's finding: `AssistantUsageEvent.data` carries `model: string` (**required, non-optional** — `session-events.d.ts:3777`) and optional `copilotUsage.totalNanoAiu` (`:3815`), fired ephemerally per LLM API call (`ephemeral: true`, `:3704`). Caco already consumes this event to record token counts (`src/dispatch-events.ts:94-108`) but discards its `model` and `copilotUsage`. Using them as the resolution source produces **exact per-turn pricing** for Auto and for any mid-request switch (including SDK-forced `cause: "rate_limit_auto_switch"` on a directly-selected model), obviating the "estimated" machinery entirely. The two `session.*` model events (`session.auto_mode_resolved`, `session.model_change`) become **display-only metadata** on the record. Event-ordering hazards dissolve: because every `assistant.usage` carries its own `model`, per-turn pricing is correct independent of when `session.model_change` fires relative to that usage event.

**Rejected alternatives.** (1) An "estimated credit" flag driven by `session.auto_mode_resolved.chosenModel` / `session.model_change.newModel`: `auto_mode_resolved` is documented as "the concrete model the session settled on **for the first prompt of an auto-mode session**" (`:7786` docblock) — session-scoped, not per-dispatch, so requests 2…N are fully unresolved unless a `model_change` happens to fire; and the "captured has no rates" test can't be trusted because on resume `parseSessionModel` writes the last `model_change.newModel` into `meta.model` (`src/sdk-session-store.ts:417-440`, called from `session-manager.ts:syncModelCache`), so a resumed Auto session's `getSessionMeta.model` is often a concrete slug — the estimation branch would silently never run. (2) The SDK's `AssistantUsageData.cost` (`:3753`, `@experimental`, "Model multiplier cost for billing purposes") is intentionally NOT used as the primary source — it is experimental and its units/multiplier semantics can drift; `copilotUsage.totalNanoAiu` is the stable per-call cost figure (mirrored by `session.usage_checkpoint.totalNanoAiu` at `:2015` for session-lifetime cross-check).

**No sub-agent filter — sub-agent turns count toward the parent record.** Sub-agent calls run inside the **same** SDK session; their `assistant.usage` events arrive on the parent dispatch's stream with `agentId` set (and often `initiator === "sub-agent"`). Today `session-throughput.recordUsage` (`src/session-throughput.ts:7-9`, header comment) explicitly *"accumulate across every assistant turn **+ subagent call** within the request"*, and the throughput snapshot the record's token columns are derived from includes those turns. An `agentId`/`initiator` exclusion would silently delete real spend and disagree with the tokens on the same row. The amendment therefore **does NOT filter** sub-agent turns out of `requestCredits`. Instead, an `initiatorBreakdown` field surfaces the split as metadata (see below); the parent's `perTurn` accumulator captures every `assistant.usage` — root and sub-agent alike — in observation order. (This is a correction: the pre-shipped `task`-tool sub-Caco-*session* path (via `agent-tools.ts`) is a different feature entirely; it produces its own top-level Caco session with its own dispatches and its own usage records, and shares nothing with this amendment.)

**Per-turn accumulator (fresh-split at capture, not at pricing).** The dispatch closure carries an ordered `perTurn: Array<TurnUsage>` initialized empty, where `TurnUsage = { model: string, freshInputTokens: number, cachedTokens: number, outputTokens: number, initiator: 'root' | 'sub-agent' | 'mcp-sampling', nanoAiu?: number }`. The existing `assistant.usage` handler (`src/dispatch-events.ts:94`) reads `inputTokens` (SDK **total** prompt), `cacheReadTokens`, `outputTokens`, `model`, `initiator`, `copilotUsage`, `agentId` via `extractProperty(event, name)` (the seam defined in `src/sdk-normalizer.ts:44` that handles the live-vs-history root-vs-`data` shape difference; `agentId` is at event root per `session-events.d.ts:3699`, `initiator` inside `data` per `:3765`), then pushes `{ model, freshInputTokens: Math.max(0, inputTokens - cacheReadTokens), cachedTokens: cacheReadTokens, outputTokens, initiator: classifyInitiator(agentId, initiator), nanoAiu: copilotUsage?.totalNanoAiu }`. **`classifyInitiator`** normalizes `initiator` into the closed three-value union: `agentId` present OR `initiator === 'sub-agent'` → `'sub-agent'`; `initiator === 'mcp-sampling'` → `'mcp-sampling'`; anything else (including unrecognized SDK values from the open-vocabulary `initiator?: string` field) → `'root'`. This keeps `initiatorBreakdown` exhaustive by construction — future SDK initiator values fold into `'root'` (safe over-attribution to the parent) rather than silently vanishing. **Fresh-split parity with `recordUsage`** (see `session-throughput.ts` around line 248, `const fresh = Math.max(0, input - cache)`) is mandatory — the per-turn credits arithmetic MUST match the token columns derived from the snapshot (which uses the same split). Because `recordUsage` bumps `requestTurns` in the same handler pass that pushes to `perTurn`, the identity `perTurn.length === requestTurns` holds in lockstep; each element is one LLM API call. An oracle pins parity between `sum(perTurn.freshInputTokens) === snapshot.requestIn` (and `cachedTokens` vs `requestCache`, `outputTokens` vs `requestOut`) for the same event stream.

**Wiring the accumulator through `applyDispatchEventEffects`.** The dispatch-events module today is stateless (`applyDispatchEventEffects(sessionId, event, deps)` at `src/dispatch-events.ts:52`); both new capabilities land as **required** members on `DispatchEventDeps` (matching the file's existing doctrine — the usage-meter member is required exactly so it can't silently fail closed): `onTurnUsage(turn: TurnUsage): void` (pushes to the dispatch-closure array in `session-messages.ts`), and `resolveRates(modelId: string): { input, cache, output } | null` (for the live per-turn contribution to `snapshot.totalCreditsPriced` inside `recordUsage`). Both are wired at `session-messages.ts:579` where `DispatchEventDeps` is constructed; the priced model list `capturePriceContext` builds locally (around `session-messages.ts:359-361`) is hoisted into the dispatch closure so `resolveRates` can read it per turn without re-deriving. Test call sites that construct `DispatchEventDeps` (~40 spots) each gain no-op stubs; this is the same ergonomic cost paid when the usage-meter member was added.

**Pricing at completion (single-source-of-truth for both columns and credits).** In `completeDispatch`, `buildUsageRecord` gains an optional `perTurn: readonly TurnUsage[]` param. **The record's token columns AND its per-class cost columns AND its `turns` field are ALL sourced from `perTurn` when `perTurn` is non-empty** — this closes the reviewer's "two accumulators, cannot reconcile" hazard end-to-end. Credits are computed **per turn** using the SAME `resolveUsageRates` helper the live path uses: for each entry, resolve `model` via `resolveUsageRates`, price `(freshInputTokens × input + cachedTokens × cache + outputTokens × output) / 1e6`, and sum. **Per-class cost identity preserved**: when at least one turn prices, the record's shipped `inputTokenCost`/`cachedTokenCost`/`outputTokenCost` fields become the sum-over-PRICED-turns of each class's tokens × that turn's rate, so `requestCredits === inputTokenCost + cachedTokenCost + outputTokenCost` continues to hold under the per-turn path exactly as under the shipped path. **When zero turns price (all-unpriced per-turn case)**, all four cost fields — `requestCredits`, `inputTokenCost`, `cachedTokenCost`, `outputTokenCost` — are `null` (NOT `0`), matching the shipped fallback-path convention for unpriced records; the identity holds vacuously (`null === null + null + null` under the same convention that already applies to the shipped record schema). Unpriced turns contribute tokens to `perModelBreakdown[m].{inputTokens,cachedTokens,outputTokens}` and to the record token totals, but zero to the per-class cost columns (in the mixed case) or leave those columns `null` (in the all-unpriced case). A turn whose model doesn't resolve → its tokens still count into `perModelBreakdown` and record totals, but its credits are `null`; it also increments `unpricedTurns` (a new record field). When `unpricedTurns > 0` but at least one turn prices, `requestCredits` is the sum of PRICED turns and `creditsComplete: false` is set. Same-request oracle (scoped): for a single-request session **with no post-`session.idle` `assistant.usage`** (see "Late `assistant.usage`" below), `snapshot.totalCreditsPriced === record.requestCredits` — the two paths call the same helper on the same rate table, so any drift within that scope is a bug pinned by test. When `perTurn` is empty (SDK didn't emit `assistant.usage` — pre-send abort, watchdog before first turn), fall back to the shipped dispatch-start-rates path (unchanged, keeps the record shape stable); `creditsComplete` is unset (absent).

**Record schema (all amendment fields OPTIONAL for backward compat).** In addition to the shipped fields, `UsageRecord` gains:
- `perModelBreakdown?: Record<string, { credits: number | null, turns: number, inputTokens: number, cachedTokens: number, outputTokens: number }>` — one entry per distinct `model` observed in `perTurn`; `credits: null` when the model didn't resolve to rates.
- `unpricedTurns?: number` — count of `perTurn` entries whose model didn't resolve to rates.
- `creditsComplete?: boolean` — `true` iff all turns priced; absent under the fallback path.
- `sdkNanoAiu?: number` — sum of `perTurn[i].nanoAiu` when any turn carries it. **Named `sdkNanoAiu` throughout (record AND bucket)** — nano-AIU is CAPI's billing unit, not credits; naming it `credits` at any layer risks conflation. The applet renders it labelled as such.
- `autoResolvedTo?: string` — set from the last observed `session.auto_mode_resolved.chosenModel` for this session, via a small module-level `Map<sessionId, string>` cache seeded lazily and evicted from `SessionRuntime.dispose()` (`src/session-runtime.ts:29`) alongside the existing `clearThroughput` + `clearSessionUsage` calls (that is the repo's per-session teardown seam; the throughput map itself is cleared there, so this cache follows the same precedent).
- `switchedDuringRequest?: { fromModel: string, toModel: string, cause?: string }` — set when a root `session.model_change` fires **during this dispatch** with `agentId` absent; captures `newModel`/`previousModel`/`cause`. This is display-only — pricing is already correct via per-turn attribution.
- `initiatorBreakdown?: { root: { credits: number | null, turns: number, inputTokens: number, cachedTokens: number, outputTokens: number }, subAgent?: { credits: number | null, turns: number, inputTokens: number, cachedTokens: number, outputTokens: number }, mcpSampling?: { credits: number | null, turns: number, inputTokens: number, cachedTokens: number, outputTokens: number } }` — a bucket is **absent** at 0 turns (root is always present when `perTurn` is non-empty because unrecognized initiators fold into it); a bucket with turns but no priced turn has `credits: null`; a bucket with any priced turn has `credits: number` = Σ that bucket's priced turns. Because sub-agent/mcpSampling credits count toward `requestCredits` (no exclusion), the identity `Σ initiatorBreakdown.*.credits (over buckets where credits !== null) === requestCredits` holds when `creditsComplete === true`. When only sub-agent turns are unpriced, `root.credits === Σ root's priced turns`, `subAgent.credits === null`, and `requestCredits === root.credits + (any priced mcpSampling)`; the tokens fields on every bucket still reflect the full accounting.

**Derived views, not independent state.** `perModelBreakdown`, `initiatorBreakdown`, `unpricedTurns`, `sdkNanoAiu`, `creditsComplete`, and per-class cost columns are pure derivations of `perTurn` computed once at `buildUsageRecord` time — no independent maintenance. `perTurn` itself is **not** persisted on the record (kept ephemeral in the dispatch closure); only its derivations land on disk. `record.turns` under the per-turn path equals `perTurn.length` and equals `Σ initiatorBreakdown.*.turns`.

**Multi-model `record.model` / `contextWindow`.** The shipped record captures `model` and `contextWindow` at dispatch start (`session-messages.ts:433-438`). Under Auto, that captured value is `'auto'` / `null`; the amendment does NOT rewrite it — readers seeking the actual model(s) that ran pivot on `perModelBreakdown` (or `autoResolvedTo` for the session-level first-prompt hint). This keeps the shipped column semantics stable and avoids an ambiguous "which model do we pick when three ran?" question at record-write time.

**Session-lifetime credit accumulator (footer authority).** `session-throughput`'s snapshot already carries session-lifetime `totalIn/totalCache/totalOut`; the amendment adds `totalCreditsPriced: number` and `totalTurnsUnpriced: number` accumulators, updated inside `recordUsage` when the caller (the extended `dispatch-events` handler via the `resolveRates` dep) passes in a resolved per-Mtok rate triple (or `null` when unresolved). The snapshot's client-facing shape (`ThroughputSnapshot`, mirrored by `ThroughputData` in `public/ts/context-footer.ts:332`) gains those two fields. This lets the footer's `estimateCost` (~`public/ts/context-footer.ts:403`) become server-authoritative under Auto: it reads `snapshot.totalCreditsPriced` directly instead of pricing `totalIn/totalCache/totalOut` at one active model's rates. The mid-request throughput broadcasts (`dispatch-events.ts:109`, `:116`, `:128`) already fire on every `assistant.usage` / `model.call_failure` / `session.compaction_complete` and their payload IS `snapshot(sessionId)` spread — the new snapshot fields ride the existing broadcasts, so live update happens without any new broadcast plumbing; the credit headline updates on the same cadence as the token counters do today. When `totalTurnsUnpriced > 0` the footer surfaces a partial marker adjacent to the headline so an under-report is never silent.

**Isolation from resume-derived meta.** "Is this dispatch Auto?" is derived from **the model id the user's send actually specified** (the dispatch config passed to the SDK), NOT `getSessionMeta.model` — the latter is rewritten by `parseSessionModel` on resume. The `perTurn` path doesn't need this test at all (attribution is by observed usage), so the resume-rewrite hazard is by construction closed. The dispatch-start-rates FALLBACK path (no `assistant.usage` observed) preserves whatever `getSessionMeta.model` returned; this is a documented edge (no worse than pre-amendment).

**Aggregation & API.** `aggregateHourly`'s bucket schema gains OPTIONAL: `sdkNanoAiu?: number` (sum of records' `sdkNanoAiu`; absent when none in bucket carry it), `perModelCredits?: Record<string, number | null>` (sum of `perModelBreakdown[m].credits` across records — **`null` for a specific model key** iff any contributing record had that key with `credits: null`; other keys in the same bucket still carry their numeric sum), `subAgentTurns?: number` (sum of `initiatorBreakdown.subAgent.turns`), and `partialRequests?: number` (count of records with `creditsComplete === false`). **Bucket-membership convention**: a record counts in exactly one of `pricedRequests` (any priced turn OR the fallback path yielded numeric `requestCredits`) vs `unpricedRequests` (zero priced turns / null `requestCredits`) — those two remain exclusive so `credits / pricedRequests` never skews; `partialRequests` is a NON-EXCLUSIVE overlay counting records with `creditsComplete === false`, so a mixed priced/unpriced per-turn record lands in `pricedRequests` AND `partialRequests`, while an all-unpriced per-turn record lands in `unpricedRequests` AND `partialRequests`. `credits` semantics: unchanged (sum of `requestCredits` where non-null; null when no priced records). A `partialRequests > 0` bucket signals "some records under-count credits" so the applet can mark it visibly — closes the "silent under-count" hazard the reviewer flagged for mixed priced/unpriced turns. `GET /api/usage/hourly` and `GET /api/usage/records` echo the new fields without new query parameters. Backward compatibility: **all new record and bucket fields are OPTIONAL**; a pre-amendment day-file record parses unchanged (`readDayFile` at `src/usage-store.ts:76-91` does an unchecked JSON parse; extra keys are ignored, missing keys become `undefined`). Consumers MUST handle absence, not assume presence — an oracle pins this rather than the trivial parse.

**Late `assistant.usage` after `session.idle`.** `completeDispatch` reads `perTurn` **once** at finalization. A `assistant.usage` arriving after `session.idle` still hits `recordUsage` (session-lifetime totals stay coherent) and its `perTurn` entry is dropped for the record. Documented; acceptable — an SDK late-arriving event past idle is a corner and the record's request-scoped snapshot is already the authoritative boundary.

**Empty-`perTurn` non-fallback edge.** `requestTurns > 0` with an empty `perTurn` is unreachable today: `recordUsage` bumps `requestTurns` in the same handler that pushes to `perTurn`, so they move in lockstep. If future changes desynchronize them, the empty-`perTurn` path still routes to the dispatch-start-rates fallback (safe under-report, never a crash).

**Docstring drift correction.** The shipped `buildUsageRecord` takes `tokens: UsageTokens`, not `snapshot` — the existing spec Design paragraph shows `snapshot` and needs an in-place fix during this amendment (Plan row 8).

**Footer follows the snapshot.** The client footer's Auto-hide-headline path is dropped: `estimateCost` (~`public/ts/context-footer.ts:403`) reads `snapshot.totalCreditsPriced` (added above); the "spent and saved never disagree about priced-vs-unpriced" comment on `resolveModelRates` (`public/ts/saved-pricing.ts:12-16`) is amended to note that spent is now server-authoritative and only the savings side still governs that property. `cacheMissCredits` (`context-footer.ts` ~`:530`) stays hidden under Auto — its per-turn-rate premise cannot be preserved when turns span multiple models. `priceSaved` (`context-footer.ts` ~`:420`) is NOT rewired in this amendment (the savings arithmetic is per-active-model and orthogonal to per-turn spend attribution) — a follow-up. A partial-marker (small "±" adjacent to the credit headline) is shown when `snapshot.totalTurnsUnpriced > 0`, so the reader knows the number under-reports. A comment on both codepaths names the difference so a later reader doesn't try to reconcile them prematurely.

## Invariants

- **Best-effort telemetry** (invariant): emission and disk writes never throw into the dispatch path — every sink and store call is guarded (matches `request-metrics-log`). A metrics failure must never fail a request.
- **Single durable collection point** (invariant): all persisted usage flows through `emitUsageRecord` inside `completeDispatch` (the sole route finalizer). No other call site appends usage records — a second emitter would double-count. Forced-clear of a wedged session is a documented exclusion, not a second path.
- **Priced by the model each turn ran on** (invariant, amended): when `assistant.usage` events are observed, each turn's tokens are priced under that turn's own `model` value. Both root-agent AND sub-agent (`agentId` set) AND `initiator ∈ {"sub-agent","mcp-sampling"}` turns count toward the same `requestCredits`, because sub-agent calls run under the parent's dispatch and their spend already accumulates into the parent request's throughput counters (`src/session-throughput.ts:5-9`). When no `assistant.usage` is observed (edge/abort), fall back to the dispatch-start captured rates. A directly-priced turn is never re-priced by a later `model_change`; a mid-request `model_change` becomes `switchedDuringRequest` display metadata, never applied retroactively.
- **Fresh-input split parity** (invariant, amended): per-turn accounting stores `freshInputTokens = max(0, inputTokens − cacheReadTokens)` — matching `session-throughput.recordUsage`'s `fresh = Math.max(0, input - cache)` (`src/session-throughput.ts:245-247`). The record's token columns and its credit arithmetic MUST both use this fresh split; the throughput snapshot (which the record inherits its token columns from when `perTurn` is empty) already uses it.
- **Single source of truth for record tokens** (invariant, amended): when `perTurn` is non-empty, the record's `inputTokens`/`cachedTokens`/`outputTokens` are the sum across `perTurn` entries (fresh-split for input). When `perTurn` is empty, they come from `markRequestComplete` (the shipped fallback). Consumers see exactly one token population per record — never a mixed snapshot-vs-perTurn view.
- **Cost frozen at completion** (invariant): `requestCredits` and any per-model breakdown are computed once, in `completeDispatch`, from the captured `perTurn` list (or fallback rates) and stored. Readers never re-price (rates drift; historical spend must stay stable).
- **Credit completeness tracked, not silently truncated** (invariant, amended): when one or more `perTurn` entries fail to resolve to rates, `requestCredits` is the sum of priced turns and `creditsComplete: false` is set; `unpricedTurns` records the count. Aggregation surfaces `partialRequests` at bucket granularity so an under-count is visible, not hidden.
- **SDK nano-AIU is not credits** (invariant, amended): `sdkNanoAiu` (sum of `copilotUsage.totalNanoAiu` across turns) is stored alongside `requestCredits` and named `sdkNanoAiu` at every layer (record, bucket, API, applet). It is CAPI's billing unit; converting it to "credits" requires an AIU↔credit ratio the SDK does not expose. Caco-computed `requestCredits` remains the primary credit figure; `sdkNanoAiu` is the corroboration signal.
- **Backward-compatible schema** (invariant): every amendment field on `UsageRecord` (`perModelBreakdown`, `unpricedTurns`, `creditsComplete`, `sdkNanoAiu`, `autoResolvedTo`, `switchedDuringRequest`, `initiatorBreakdown`) and on `HourlyBucket` (`sdkNanoAiu`, `perModelCredits`, `subAgentTurns`, `partialRequests`) is OPTIONAL. Pre-amendment day-files parse unchanged. **Consumers MUST handle absence** rather than assume presence — an oracle pins the null/undefined handling in the applet path.
- **Pure builder + pure aggregation** (invariant): `buildUsageRecord` and `aggregateHourly` do no I/O, so both are ref-impl testable without a session or disk.
- **Bounded partition count** (invariant): a windowed read touches only the ≤ (window-days + 1) day-partition files intersecting the window, never the whole history.

## Considerations

- **Cost-math parity with the footer.** The footer prices client-side (`public/ts/saved-pricing.ts`, `ModelInfo`→rates); the store prices server-side (`src/model-billing.ts`, `SDKModelInfo`→rates). The two runtimes are separate builds (`tsconfig.frontend.json` scopes `public/ts/**` only; `tsconfig.json` excludes `public`), so importing `model-billing` into browser code is not clean — the pure *arithmetic* is duplicated, not shared. Mitigation: the parity oracle asserts identical costs given identical resolved rates AND covers the divergence-prone cases — segment-boundary **variant fallback**, `null` rates, and **missing cache/output rate** — not just the happy path. (Extracting one isomorphic node-free pricing module is an option deliberately not taken now to avoid build-graph churn.)
- **Model resolution at dispatch start (fallback path only).** Capture the model from the resolved dispatch config (the model the SDK session is actually running), not `getSessionMeta` at completion; `sessionManager.getModels().find(id)` → `modelCostSummary(m)` gives rates + `contextWindow`, with the variant fallback for `-1m`/`-internal` ids; unresolved → null costs (token-only record), never a crash. **Primary path is per-turn attribution from `assistant.usage` (see Amendment).** The dispatch-start capture remains as the fallback when the SDK emits no `assistant.usage` for the request (pre-send abort, watchdog before first turn). Session-meta drift on resume (`parseSessionModel` rewriting `meta.model` to the last `model_change.newModel` — `src/sdk-session-store.ts:417-440`) is by construction unreachable from the primary path, since attribution reads observed usage, not stored meta.
- **Auto-mode discount not surfaced; nano-AIU corroborates.** The SDK's `modelCostSummary` exposes each concrete model's per-Mtok token prices (source of truth for billing display — `spec-budget.md:60`: "The legacy `billing.multiplier` is dead" — the dead field is genuinely dead, not a hook we can bring back). Any Auto-mode routing discount lives upstream in CAPI's cost accounting and surfaces via `AssistantUsageData.copilotUsage.totalNanoAiu`, which the record persists as `sdkNanoAiu`. Caco's `requestCredits` (`tokens × per-Mtok`) is therefore a **best-available credit estimate** — exact per turn under the resolved model, but not adjusted for any Auto discount. The applet renders both figures (`sdkNanoAiu` labelled in nano-AI-units, not conflated with credits) so drift is visible.
- **Live-vs-history event shape.** `dispatch-events.ts` already normalizes payload shape via `extractProperty(event, name)` because "live events carry `success` at the root, history events under `data`" (`src/dispatch-events.ts:131-137`). The `perTurn` accumulator MUST read `model`/`inputTokens`/`cacheReadTokens`/`outputTokens`/`copilotUsage`/`initiator`/`agentId` through the same seam. `agentId` is at the event root (`session-events.d.ts:3699`); `initiator` is inside `data` (`:3765`). `extractProperty` handles the root-vs-data distinction; integration oracles cover a captured **real** live payload for each, not just synthetic shapes.
- **UTC partitioning vs local display.** Records store UTC `ts`; day-files are UTC dates; `aggregateHourly` buckets in UTC. The applet renders bucket labels in the browser's local time. Keeping storage UTC avoids DST/timezone drift in the partition key (the scheduler's missing-TZ handling is a cautionary precedent).
- **Request vs turn granularity.** One record per request (send→idle), not per turn — matches the in-memory request-scoped counters (`requestIn/Cache/Out`, reset by `resetRequest`). Steering (`sendStream`) adds to the ongoing request without reset, so a steered request emits exactly one combined record at final idle. `completeDispatch` reads the request-scoped figures (via `markRequestComplete` / `snapshot`) before the next send's `resetRequest` clears them.
- **Concurrency & corruption.** Appends are synchronous single-line `appendFileSync` in append mode (atomic per line on POSIX), so parallel sessions writing the same day-file don't interleave within a line; a partially-written line (crash mid-append) is skipped on read, not fatal. Single-process assumption — no cross-process lock (documented, not built).
- **Retention.** Not implemented now; day-partitioning makes a future prune trivial (delete files older than N days). A configurable prune (default off / conservative) is a noted non-blocking follow-up.

## Risks and Mitigations

- Teardown path bypasses completion (forced-clear / model switch) → model switch is blocked mid-dispatch by the busy guard; forced-clear of a wedged session is a documented exclusion (unreliable counters); tests: normal cancel emits one record, pre-send abort emits none.
- Mid-request model swap misprices → busy guard rejects model change during dispatch + rates captured at start; test that a swap-while-busy is 409 and the record prices under the original model.
- Double-counting if a second emit site appears → single-collection-point invariant + a test asserting `completeDispatch` is the only caller.
- Cost/behavior drift vs footer → parity oracle covering arithmetic + variant fallback + null + missing-rate cases. **Post-amendment: footer's `estimated` figure reads authoritative `snapshot.totalCreditsPriced` (extended in `session-throughput`), so drift can only enter via a rate table divergence, still covered by the existing parity oracle.**
- Unpriced usage read as zero spend → aggregation returns `credits: null` + `priced/unpricedRequests`; applet renders unpriced distinctly. **Post-amendment: an Auto request produces `perModelBreakdown` + a `requestCredits` from `assistant.usage`. Turns whose model doesn't resolve trigger `creditsComplete: false` + `unpricedTurns`; buckets containing such records increment `partialRequests` so the applet can visibly mark them (not a silent under-count).**
- Sub-agent turns falsely excluded from parent's credits → the amendment does NOT filter `agentId`-present or `initiator ∈ {"sub-agent","mcp-sampling"}` events out of `requestCredits`, because those turns already accumulate into the parent's throughput token counters (`session-throughput.ts:5-9`) and the record's token columns come from the same source; filtering credits alone would create a silent tokens-vs-credits disagreement. `initiatorBreakdown` surfaces the split (`root`/`subAgent`/`mcpSampling`) as a display cut, and an oracle pins `sum(initiatorBreakdown.*.credits) === requestCredits` when all turns priced. (The `task`-tool sub-Caco-*session* path — a whole separate top-level Caco session with its own dispatch record — is a different feature and is naturally isolated by the outer dispatch boundary.)
- SDK `assistant.usage` shape drift (event moved, field renamed, `copilotUsage` removed) → `copilotUsage` is already optional in the SDK (`:3815`), so its absence is normal, not drift; the `perTurn` accumulator is best-effort (missing fields default to 0, missing event → fallback path); tests cover the "no `assistant.usage` at all" case and pin the field names against the shipped SDK dts version. A future SDK version renaming `model` (required non-optional today at `:3777`) would cause fallback-path pricing only, not a crash.
- Live-vs-history payload confusion → all reads through `extractProperty`; integration tests use both a captured live payload and a captured history payload (not synthetic).
- Records mis-attributed as directly priced when Auto-mode is on (resume rewrites `meta.model`) → primary path attributes by observed `assistant.usage.model`, not `meta.model`; fallback path is documented and only reachable when no usage was observed.
- `switchedDuringRequest` metadata on a directly-selected model with `cause: "rate_limit_auto_switch"` → the row is priced under the model that ran each turn (per-turn attribution handles this correctly); the metadata field just makes such requests findable for review. **`model_change` event ordering vs `assistant.usage` is irrelevant to pricing**: each `assistant.usage` carries its own required `model`, so per-turn attribution is stable regardless of when `session.model_change` fires relative to a usage event.
- Late `assistant.usage` after `session.idle` → `completeDispatch` reads `perTurn` **once** at finalization and `dispatchCompleted` is idempotent, so any late usage is dropped for the record (session-lifetime totals stay coherent via `recordUsage`). Documented; edge only.
- `autoResolvedTo` map unbounded → the module-level `Map<sessionId, string>` cache is wired into `SessionRuntime.dispose()` (`src/session-runtime.ts:29`) alongside the existing `clearThroughput` / `clearSessionUsage` calls so per-session state evicts in lockstep.
- Unbounded scan as history grows → day-partitioned reads bound the file count to the window; mtime/size cache avoids re-parsing unchanged past-day files on frequent polls.
- Applet mis-theming → tokens-only CSS, greppable for hex/undefined-vars (spec-style oracle); visual signoff under ≥1 dark + 1 light theme.

## Rationale

`spec-budget.md` built a rich in-memory per-session model (`session-throughput.ts`) and an ephemeral bench log (`requests.jsonl`) but explicitly persists nothing across restart. This spec adds the durable, queryable layer so spend is analyzable over time and across sessions. The date-partitioned JSONL store mirrors the repo's existing file-store pattern (schedule/memory/session-meta) rather than introducing a database, and the sink abstraction keeps the collection point single while letting future consumers (rollups, export, alerting) attach without touching dispatch.

**Retired designs.** An earlier iteration of this amendment proposed an "estimated credit" flag driven by `session.auto_mode_resolved` / `session.model_change` with an `estimatedCredits` bucket field, `estimatedFromModel`, `resolvedVia`, and a footer `~` prefix. That machinery is retired: per-turn attribution off `assistant.usage` gives exact per-turn prices (not estimates), no session-scoped `auto_mode_resolved` staleness problem, and no ambiguity about which model priced a turn. If you encounter that vocabulary in prior review comments or drafts, ignore it — the current design uses `perModelBreakdown` + `creditsComplete` + `unpricedTurns` instead.
