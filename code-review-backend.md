# Backend code review — brutal pass

## Summary

- Session lifecycle is stateful in too many places: `SessionState`, `SessionManager`, `dispatchState`, websocket subscriptions, output registry, queues, and disk metadata all encode pieces of one lifecycle without a single owner.
- The flaky resume / switch / start reports match real races: per-client session transitions are not serialized, switch completion is last-writer-wins, and shared-client recovery drops active sessions without a lifecycle transaction.
- Silent sentinels are common: corrupted JSON, missing files, malformed SDK events, and parse failures collapse to `null`, `undefined`, `[]`, or `{}` and later code treats them as legitimate no-data.
- Wrong abstractions create hidden contracts: cwd is used as a session key, extension loading mutates global maps, and metrics/storage helpers expose best-effort data as if it were validated state.
- Comment cleanup removed only comments that restated code or created visual section noise; no logic, names, imports, or formatting were changed intentionally.
