# Files applet V7 no-session mode — spec review

Reviewed against `code-quality.md`, especially implicit coupling: URL shapes and boot-mode reachability must have a single owner, not scattered comments and matching assumptions.

## BLOCKER findings

### BLOCKER-1 — `routeOpenExternal` is not sessionless-safe today

The spec says sessionless mode can reuse `routeOpenExternal` with no backend changes (§4.3), but every external viewer factory except the final `/api/file` fetch first calls `shell.api.watchPath(absPath, { scope: 'file' })`:

- `applets/files/markdown-viewer.js:316-325`
- `applets/files/image-viewer.js:183-192`
- `applets/files/html-viewer.js:79-88`
- `applets/files/source-viewer.js:152-171`
- `public/ts/applet-runtime.ts:641-644` throws `No active session for watchPath`

`routeOpenExternal` catches that error, destroys the container, and returns without a tab or inline error. So the primary acceptance items for sessionless markdown/image/html/source cannot pass as specified.

Fix suggestion: make sessionless external opens explicitly no-watch. For example, pass `{ readOnly: true, watch: false }` from `bootSessionless`/`routeOpenExternal`, and update each viewer factory to skip `watchPath` when `opts.watch === false` while still doing the initial `/api/file?path=` load. Keep watch behavior unchanged in session mode.

### BLOCKER-2 — `file-finder` deletion contradicts the no-finder non-goal

§3 says sessionless mode does not support the file-finder picker and only shows the file in `openPath`. But §4.6 / acceptance 13 require `?applet=file-finder&root=ABS` to redirect to `?applet=files&openFinderRoot=ABS`. A URL with only `openFinderRoot` has no `openPath`, so the proposed `bootSessionless({ openPath })` path would render the empty pane instead of preserving the old sessionless file-finder behavior.

This is an actual regression surface: old chat/context links and bookmarks to `file-finder?root=` currently work without a session because the stub falls through to the standalone finder.

Fix suggestion: choose one contract and make it explicit. Either keep sessionless finder support in V7 by handling `openFinder=1&openFinderRoot=ABS` in `bootSessionless` (current `openPicker` already permits `rootOverride` without a session), or defer deleting `applets/file-finder/` until finder support is intentionally replaced. If the regression is accepted, remove acceptance 13's file-finder success claim.

### BLOCKER-3 — the permanent redirect owner is specified in the wrong layer

§4.6/§6.2 says the unconditional redirect lives in `applet-store.ts` as a server-side 302. `applet-store.ts` only resolves directories/assets for `/api/applets/:slug/load` and cannot redirect the browser URL. The load endpoint is a POST returning JSON; an HTTP 302 there would redirect the fetch, not the top-level page. The top-level `/?applet=...` request is handled in `server.ts:98-106`, before static files.

Fix suggestion: specify the exact owner. The clean server-side place is `server.ts`'s `app.get('/')` handler before sending `cachedIndexHtml`: inspect `req.query.applet`, compute the canonical target, preserve unknown query params, and `res.redirect(302, '/?' + target.toString())`. Alternatively make this a client-router rewrite in `public/ts/router.ts`, but then it is not an HTTP redirect and acceptance 12 must change.

## IMPORTANT findings

### IMPORTANT-1 — capability flags must cover generated chrome, not only `content.html`

`content.html` chrome elements are:

- `#feRepo` repo label
- `#feFollow` follow-edits chip
- `#feOpen` finder `+` button
- `#feTabs` tab strip
- `#fePaneEmpty` empty-state message
- `#feNotGit` not-a-git-repo message

`script.js` also generates user-facing chrome:

- tab close `×`
- per-tab viewer toggle `.files-viewer-toggle`
- markdown mode toggle `.files-mode-toggle`
- per-viewer chrome buttons `.files-chrome-buttons` / Save
- per-tab chrome error `.files-tab-error`
- image zoom HUD

The spec's four flags are directionally right, but the wiring description is incomplete. `canDiff` cannot be implemented by hiding a toolbar entry because the diff affordance is generated by `TabContainer.updateToggle()` from `viewerRegistry`. `canEdit` must affect Markdown modes, Save chrome, and Ctrl/Cmd+S. `canFollowEdits` must prevent `updateFollowButton()` from re-showing the chip after `routeOpenExternal` sets `followEdits = false`.

Fix suggestion: add an `applyCapabilities(capabilities)` design section and require these call-site changes: `updateToggle` filters out `diff` when `!canDiff`; `MarkdownViewer` receives read-only/canEdit and exposes no edit mode or Save; `updateFollowButton` returns hidden when `!canFollowEdits`; `#feOpen` is hidden when `!canPersist`; `#feNotGit` is always hidden in sessionless.

### IMPORTANT-2 — Markdown Save needs a code-path guard, not only hidden UI

`MarkdownViewer` gets session context indirectly from being opened in a session-mode tab. Save itself writes to `/api/files...` and does not check session or read-only state (`markdown-viewer.js:145-197`). The constructor already has `_readOnly`, and `getModes()` hides Edit when read-only, but `getChromeButtons()` still returns a Save descriptor and Ctrl/Cmd+S calls `save()` whenever `isDirty()` is true.

In normal UI this may be unreachable, but V7's goal is boot-boundary correctness. Hidden buttons are not a sufficient invariant for a write method.

Fix suggestion: make the wrong thing unrepresentable: if `_readOnly`/`!canEdit`, `getChromeButtons()` returns `[]`, the keydown handler does not call save, `setMode('edit')` refuses, and `save()` starts with a read-only guard. This is small and protects future callers.

### IMPORTANT-3 — removing the `if (!sessionId)` guards wholesale is unsafe and contradicts §7

§5 says to drop ~18 `if (!sessionId) return` guards, while §7 says to keep persistence guards as belt-and-suspenders. The current guards are not all accidental:

- `schedulePersist()` and `flushPersistBeacon()` are called from generic tab/chrome/beforeunload paths.
- `fetchSnapshot()` is a session-mode network call.
- `applyAgentState()` protects the `/api/sessions/:sid/file-edits/open` path.
- `openPicker()` / `runPickerFetch()` intentionally allow `rootOverride` without a session.

Fix suggestion: narrow the spec. Move session-only subscriptions and controls behind `bootSession`, but keep local guards at asynchronous boundaries, beforeunload, and public-ish methods that may be reached by future wiring. The code-quality goal is fewer reachable sessionless paths, not deleting cheap boundary assertions.

### IMPORTANT-4 — URL-shape ownership is still implicitly coupled

The contract across old and new URLs is scattered across stub scripts, `public/ts/context-footer.ts`, `public/ts/input-router.ts`, `applets/text-editor`, `image-gallery`, `session-context`, `html-viewer`, `git-status`, and docs. The magic params are `path`, `root`, `file`, `staged`, `ref`, `openPath`, `openFinder`, `openFinderRoot`, and `diffMode`. A small change in any one file can silently break old links.

Fix suggestion: add a single redirect-target builder for deprecated slugs and unit-test it. If the redirect is server-owned, put a pure helper near the `server.ts` redirect route, e.g. `legacyAppletRedirectTarget(slug, URLSearchParams): URLSearchParams | null`. For new link callsites, add a small shared client helper for `files&openPath` / `files&openFinderRoot` where TypeScript callsites can use it. The spec should identify this as the URL contract owner.

### IMPORTANT-5 — stub deletion can be one PR, but only with redirect tests before deletion

Shipping #10 + #11 atomically is reasonable for a single deployed artifact, but deleting the directories makes redirect failure catastrophic: old URLs become `Applet not found`. Regressing surfaces include old chat links for `markdown-viewer`, `image-viewer`, `html-viewer`, `file-finder`, `git-diff`, plus live long-tail links from `text-editor`, `image-gallery`, `session-context`, `html-viewer`, and git-status file-finder links if not all are updated in the same PR.

Fix suggestion: keep one PR if desired, but require the redirect helper and tests to land in the same commit before directory deletion. Acceptance should include one test per legacy slug and an unknown-param preservation case. If deploys are not strictly atomic, land redirect support first and delete stubs in a follow-up.

### IMPORTANT-6 — redirect parameter preservation is under-specified

The existing stubs clone `new URLSearchParams(p)` and delete only translated params, so unknown params are preserved. V7 mentions old URLs but does not explicitly require unknown-param preservation. This matters for future params like `line`, `openLine`, or UI flags, and for `git-diff`'s current `ref` behavior.

Fix suggestion: add a redirect rule: preserve all query params except `applet` and params intentionally translated/dropped. Add acceptance for `?applet=markdown-viewer&path=/x.md&line=42` redirecting to `files&openPath=/x.md&line=42`. Specify `git-diff?ref=` behavior from the V6 stub: ref-bearing URLs currently redirect to `git-status`, not `files`.

### IMPORTANT-7 — sessionless-to-session transition is not covered

`appletAPI.onSessionChange` can fire after an applet loaded with no active session if the user activates a session later in the same page. The spec says `bootSessionless` has no session subscriptions, which makes sessionless boot immutable, but acceptance 10 only covers switching between live sessions.

Fix suggestion: explicitly state the invariant. Either sessionless boot remains sessionless until the applet is reloaded/navigated, or it subscribes to session changes and upgrades to `bootSession`. Add an acceptance item for opening `?applet=files&openPath=/abs/x.md` with no session, then activating a session.

## MINOR findings

### MINOR-1 — boot boundary approach is good, but the shared wiring count is understated

The actual bottom-of-IIFE wiring (`script.js:3452-3589`) includes URL-param handling, state updates, session events, session changes, initial metadata, persistence, and final UI updates. A shared base class would still be the wrong abstraction under `code-quality.md` (unnecessary layer / wrong abstraction), but §6.4's "fewer than ten lines" claim is too optimistic.

Fix suggestion: keep the two flat functions, but describe shared plain functions explicitly: `applyCapabilities`, `wireUrlParamsForSession`, `wireUrlParamsForSessionless`, `openInitialSessionlessPath`, and the existing helpers. Avoid a base class.

### MINOR-2 — acceptance should cover route-open failure UI

Acceptance 8 says unreadable paths show the viewer error UI. With today's factories, errors before the viewer attaches (especially `watchPath`) destroy the tab and log only to console. Even after the no-watch fix, a bad `openPath` with no matching viewer or a failed factory should produce an inline empty-pane error.

Fix suggestion: add acceptance for `routeOpenExternal` factory failure rendering a visible error tab or empty-pane error, not a silent console warning.

### MINOR-3 — `src/routes/file-edits.ts` deferral is correct

The spec correctly defers `src/routes/file-edits.ts` / store renames to V7 #12. The route remains session-scoped and unrelated to sessionless `/api/file?path=` reads.

### MINOR-4 — roadmap alignment is mostly correct

The spec matches V7 buckets #10, #11, and #13 at a high level, and correctly defers #12. The only roadmap mismatch is the file-finder sessionless behavior: deleting the stub before preserving `file-finder?root=` changes the #10 back-compat story.

### MINOR-5 — no ASCII or Mermaid diagrams found

The spec contains no ASCII or Mermaid diagrams. The risk section is a Markdown table, not a diagram.
